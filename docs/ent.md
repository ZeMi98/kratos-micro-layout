# ent 全流程：从建表到生产可用

本文覆盖 `app/user_center` 的存储层，以 [ent](https://entgo.io) v0.14.6 为准。
ent 是模板保留的唯一 ORM：schema 用 Go 写，客户端/查询/迁移代码全部生成，
repo 只手写「DO ↔ PO 转换 + 查询组装 + 错误映射」这一薄层。

分层契约（谁能 import 谁、DO/PO 边界）见 [AGENTS.md](../AGENTS.md)，本文只讲 ent 这一条链路：

```
 手写 schema/*.go ──make ent──► 生成的 client/query/migrate 代码
                                        │
                          手写 *_repo.go（实现 biz.XxxRepo）
                                        │
                       data.ProviderSet ──make wire──► wire_gen.go
                                        │
                    configs/<service>.yaml（driver / source / auto_migrate）
                                        │
                        本地：ent Schema.Create 自动建表
                        生产：版本化 SQL 迁移，发布前执行
```

## 目录与产物

`app/user_center/internal/data/ent/`：

| 路径 | 谁写的 | 说明 |
|---|---|---|
| `schema/user.go` | **手写** | 一个 entity 一个文件：字段、索引、mixin |
| `schema/mixin.go` | **手写** | 跨 entity 复用的字段组（`IDMixin`、`TimeMixin`） |
| `generate.go` | **手写** | `//go:build ignore` 的 codegen 入口，`make ent` 就是跑它 |
| `data.go` | **手写** | `ProviderSet`、`NewData`（开连接、按需自动迁移）、驱动映射 |
| `user_repo.go` | **手写** | 实现 `biz.UserRepo`；`toBiz(po)` 做 PO → DO |
| `client.go` / `tx.go` / `mutation.go` / `ent.go` | 生成 | 客户端、事务、变更载体 |
| `user.go`、`user_create.go`、`user_query.go`、`user_update.go`、`user_delete.go` | 生成 | 每个 entity 一套 CRUD 构造器 |
| `user/`、`predicate/`、`hook/`、`runtime/`、`enttest/` | 生成 | 列名常量与 where 谓词、断言、钩子、默认值注册、测试辅助 |
| `migrate/schema.go`、`migrate/migrate.go` | 生成 | 表结构描述（列/索引/主键）与迁移执行器 |

**只有前 5 行是可以改的**，其余文件头部都写着 `// Code generated by ent, DO NOT EDIT.`；
改了也会在下次 `make ent` 被覆盖。

## 第 1 步：写 schema（建表）

一个 entity = 一张表。`schema/user.go`：

```go
type User struct{ ent.Schema }

func (User) Mixin() []ent.Mixin {
	return []ent.Mixin{IDMixin{}, TimeMixin{}}   // id / created_at / updated_at
}

func (User) Fields() []ent.Field {
	return []ent.Field{
		field.String("username").Unique().NotEmpty(),
		field.String("email").Unique(),
		field.String("phone").Default(""),
		field.String("password").Sensitive(),
		field.Int32("status").
			GoType(biz.UserStatus(0)).              // 列类型 int32，Go 侧是 biz.UserStatus
			Default(int32(biz.UserStatusActive)),
	}
}

func (User) Indexes() []ent.Index {
	return []ent.Index{index.Fields("username"), index.Fields("status")}
}
```

映射规则与几个必须知道的点：

- **表名**：ent 把 entity 名复数化，`User` → `users`；列名用字段名的 snake_case。
  需要自定义时加 `entsql.Annotation{Table: "..."}` / `field.String("x").StorageKey(...)`。
- **主键不自增**：本项目的主键是 biz 层用雪花算法分配的 int64，所以 `IDMixin` 必须带
  `Annotations(entsql.Annotation{Incremental: &autoIncrement})`（`autoIncrement := false`）。
  ent 对数值主键**默认开启自增**，不加这个注解，生成的 `migrate/schema.go` 里 id 列会变成
  `Increment: true`，数据库就会和应用抢着发号。
  对应地，repo 的 create 必须显式 `.SetID(u.ID)`。
- **`GoType`**：让列在 Go 侧用领域类型（这里是 `biz.UserStatus`），
  repo 里就能直接 `Status: po.Status` 而不必手动转换。
  代价是 `schema` 包 import 了 `biz` —— 这是模板接受的唯一一处「data 反向依赖 biz 类型」，
  换来的是 DO/PO 之间少一层枚举翻译。
- **`Sensitive()`**：该字段不会出现在生成的 `String()`/日志里。密码、密钥一律加。
- **`Unique()`** 生成唯一索引；repo 侧要把 ent 的约束错误翻译成业务错误（见第 3 步）。
- **软删除**：本模板没有用 ent 的 mixin 做软删除，而是用 `status` 字段 +
  每条查询都带 `user.StatusNEQ(biz.UserStatusDeleted)`。要改成 ent 拦截器（`ent.Intercept`）
  或 `mixin.SoftDelete` 也可以，但要保证**所有**读路径一致，否则会读到已删数据。

## 第 2 步：生成代码

```bash
make ent          # 等价于 cd app/user_center/internal/data/ent && go run generate.go
```

`generate.go` 的内容就三行有效代码：

```go
entc.Generate("./schema", &gen.Config{
	Package: "kratos-micro-layout/app/user_center/internal/data/ent",
})
```

- 它用 `entc`（库形式）而不是 `go:generate ent`，好处是**不需要安装 ent CLI**，
  版本跟着 `go.mod` 里的 `entgo.io/ent` 走，不会出现「本地 CLI 版本和依赖版本不一致导致生成结果抖动」。
- `Package` 必须等于这个目录的真实 import path —— 新服务从模板孵化后要**同步改这一行**，
  否则生成的代码 import 回旧模块。
- `./schema` 是**相对当前工作目录**的，所以 `make ent` 会先 `cd` 进去。
  在仓库根目录直接 `go run app/user_center/internal/data/ent/generate.go` 会报
  `schema directory not found`。

生成后先编译一次再继续：

```bash
go build ./... ./app/user_center/...
```

## 第 3 步：写 repo（让表可用）

repo 是 `biz` 声明的接口的实现，构造函数**返回接口而不是具体类型**，
这样 `data` 的细节不会泄漏到上层：

```go
func NewUserRepo(data *Data) biz.UserRepo { return &userRepo{data: data} }
```

一个 repo 里只做四件事：

**1）DO ↔ PO 转换。** PO 就是 ent 生成的 `*ent.User`，DO 是 `*biz.User`。
读方向用一个自由函数集中转换：

```go
func toBiz(po *User) *biz.User {
	if po == nil { return nil }
	return &biz.User{ID: po.ID, Username: po.Username, /* … */ }
}
```

写方向 ent 用的是链式 `SetXxx`，不必再造 PO 结构，直接摊在 create 里即可。

**2）查询组装。** 把 `biz.ListOptions`（filter / order_by / offset / limit）翻译成 ent 查询。
AIP 表达式解析交给 `github.com/go-kratos/aip-go/ents`：

```go
query := r.data.db.User.Query().
	Where(user.StatusNEQ(biz.UserStatusDeleted)).
	Where(ents.ApplyFilter(options.Filter))

total, err := query.Clone().Count(ctx)          // 分页前先算总数

pos, err := query.
	Order(ents.ApplyOrderBy(options.OrderBy), user.ByID()).  // 末尾恒定按 id 排序
	Offset(options.Offset).Limit(options.Limit).All(ctx)
```

offset 分页**必须有确定的全序**，否则翻页会出现重复/漏行；雪花 id 本身按时间递增，
拿它兜底既稳定又符合默认「最新在前」的直觉。

**3）错误映射。** 驱动错误不许冒到 biz 以上，否则上层就要认识 ent：

```go
if IsNotFound(err)        { return nil, biz.ErrUserNotFound }
if IsConstraintError(err) { return nil, biz.ErrUserAlreadyExists }
```

`IsNotFound` / `IsConstraintError` 都是 ent 生成的判定函数。
唯一索引冲突（username / email 重复）走 `IsConstraintError` 这一支。

**4）事务。** 需要跨表原子性时用生成的 `Tx`：

```go
tx, err := r.data.db.Tx(ctx)
if err != nil { return err }
// 用 tx.User.Create()… 代替 r.data.db.User.Create()…
if err := tx.Commit(); err != nil { return err }   // 出错路径记得 tx.Rollback()
```

单表单语句不需要事务。

## 第 4 步：接线

1. `internal/data/ent/data.go` 的 `ProviderSet` 里登记构造函数：
   `wire.NewSet(NewData, NewUserRepo)`。
2. `internal/data/data.go` 的 `ProviderSet` 已经指向 `ent.ProviderSet`，一般不用动。
3. `make wire` 重新生成 `wire_gen.go`（改了构造函数签名也要跑）。
4. 配置 `configs/user_center.yaml`：

```yaml
data:
  database:
    driver: mysql          # mysql（默认）或 postgres
    source: '${DB_SOURCE:root:123456@tcp(127.0.0.1:3306)/user_center?parseTime=true&loc=Local}'
    debug: true            # 打印每条 SQL，只在开发环境开
    auto_migrate: true     # 启动时 Schema.Create；生产关掉，见第 6 步
```

- `source` 用 `${VAR:default}` 占位符，凭据从环境变量（`KRATOS_DB_SOURCE`）或 Nacos 配置中心注入，
  不进版本库。占位符规则见 [README 的「配置说明」](../README.md)。
- MySQL DSN 两个参数别省：`parseTime=true`（否则 DATETIME 读成 `[]byte`）、
  `loc=Local`（否则时间按 UTC 解释，读写之间会差一个时区）。
- 驱动名和 ent 方言不总是一样，映射写在 `data.go` 的 `openClient` 里：
  配置填 `postgres`，实际 `sql.Open` 用 `pgx`（`_ "github.com/jackc/pgx/v5/stdlib"` 已 import）。
  换 PostgreSQL 只改 `driver` + `source` 两行，代码不用动。

## 第 5 步：本地开发

```bash
make middleware-up     # 起 MySQL / Redis / Nacos（deploy/middleware/docker-compose.middleware.yaml）
make run-user-center   # auto_migrate=true，启动时自动建表
```

compose 里的 `MYSQL_DATABASE: user_center` 负责**建库**；ent 的 `Schema.Create` 只**建表**，
库不存在时会直接连接失败。用自己的 MySQL 实例时，先手动 `CREATE DATABASE user_center`
（字符集建议 `utf8mb4` / `utf8mb4_unicode_ci`）。

`auto_migrate` 调的是 ent 的 `Schema.Create(ctx)`，它的行为要记清楚：

- 建缺失的表、加缺失的列/索引；
- **默认不删**已存在但 schema 里已经没有的列和索引（`WithDropColumn` / `WithDropIndex` 默认 false）；
- 不做有损的类型变更（改类型、缩短长度这类它不敢动）。

所以本地库跑久了会和 schema「对不齐」—— 这是设计如此（宁可漏删也不误删数据），
不是 bug。开发期最干净的做法是重建：

```bash
docker compose -f deploy/middleware/docker-compose.middleware.yaml down -v && make middleware-up
```

## 第 6 步：生产可用（版本化迁移）

生产环境把 `auto_migrate` 关掉，表结构变更作为**独立、可评审、可回滚**的一步，
在新版本二进制发布**之前**执行。理由：应用启动时自动改表无法评审、无法灰度、
多副本并发启动会互相打架，而且 ent 的自动迁移不会删列，长期必然产生漂移。

### 方案 A：Atlas 版本化迁移（推荐）

ent v0.14.6 自带的 `cmd/ent` 已经**没有** `migrate` 子命令，增量迁移统一由
[Atlas CLI](https://atlasgo.io) 负责（它能直接读 ent schema）。

```bash
# 安装（二选一）
brew install ariga/tap/atlas
curl -sSf https://atlasgo.sh | sh
```

在仓库根放一份 `atlas.hcl`：

```hcl
env "ent" {
  src = "ent://app/user_center/internal/data/ent/schema"
  # 一个一次性的“影子库”，Atlas 用它计算 schema 差异；需要 Docker
  dev = "docker://mysql/8/dev"
  migration {
    dir = "file://deploy/script/migrations"
  }
  format { migrate = diff }
}
```

日常流程：

```bash
# 1) 改完 schema、make ent 之后，生成一条带时间戳的迁移
atlas migrate diff add_user_avatar --env ent
#    -> deploy/script/migrations/20260904xxxxxx_add_user_avatar.sql

# 2) 人工评审这个 .sql（这一步不能省）
# 3) 维护目录校验和（atlas.sum），迁移文件不许手改内容
atlas migrate hash --dir file://deploy/script/migrations

# 4) 静态检查：破坏性变更（删列、改类型、加非空列无默认值）会被标出来
atlas migrate lint --env ent --latest 1

# 5) 应用到目标库（凭据从环境变量/密管系统注入，不要写进脚本）
atlas migrate apply --env ent \
  --url "mysql://root:${MYSQL_PWD}@tcp(127.0.0.1:3306)/user_center"
```

`deploy/script/migrations/` 连同 `atlas.sum` 一起提交；每个环境用同一批文件，
Atlas 靠 `atlas_schema_revisions` 表记录已执行到哪一条，重复执行是安全的。

### 方案 B：不装额外工具，导出全量 DDL

`Schema.Create` 有个只写不执行的孪生方法 `WriteTo`，可以把当前 schema 对应的建表语句打印出来。
它需要连一个**空的**库来计算差异（本地 `make middleware-up` 起的 MySQL 就够）：

```go
//go:build ignore

// 用法：cd app/user_center/internal/data/ent && go run dumpsql.go > /tmp/schema.sql
package main

import (
	"context"
	"log"
	"os"

	ent "kratos-micro-layout/app/user_center/internal/data/ent"
)

func main() {
	dsn := os.Getenv("DSN") // 例：root:123456@tcp(127.0.0.1:3306)/user_center?parseTime=true
	client, err := ent.Open("mysql", dsn)
	if err != nil {
		log.Fatal(err)
	}
	defer client.Close()
	if err := client.Schema.WriteTo(context.Background(), os.Stdout); err != nil {
		log.Fatal(err)
	}
}
```

导出的 SQL 适合放到 `deploy/script/schema.sql`，用于全新环境初始化或 DBA 评审。
它**不是增量迁移**：schema 演进之后要靠人对比。要做持续演进，用方案 A。

### 上线顺序与大表变更

- **先迁移，后发布**：迁移必须向后兼容当前正在跑的版本（只加可空列/带默认值的列、加索引、加表）。
- **expand → contract**：改名/删列拆成两次发布 —— 先加新列并双写，切读，下一个版本再删旧列。
  这样任何一个时刻回滚都不会缺列。
- **大表 DDL**：加索引/改类型可能长时间持锁。MySQL 8 多数加列是 INSTANT，但改类型、
  加全文索引等仍需 COPY；线上用 `ALGORITHM=INPLACE, LOCK=NONE` 或 gh-ost / pt-online-schema-change。
- **超时**：迁移不走服务的 `server.http.timeout`，但要在发布流水线里给足时间并设告警。
- **权限**：迁移用的账号需要 DDL 权限，应用运行账号只给 DML —— 这也是关掉
  `auto_migrate` 的一个附带好处。

## 新增一张表的检查清单

1. `schema/<resource>.go`：entity + mixin + 字段 + 索引；主键沿用 `IDMixin`（不自增）。
2. `make ent`，然后 `go build ./... ./app/user_center/...` 确认生成代码可编译。
3. `biz`：声明 DO、`<Resource>Repo` 接口、usecase 与 `Err<Resource><Cause>` 错误。
4. `ent/<resource>_repo.go`：实现接口，`New<Resource>Repo(data *Data) biz.<Resource>Repo`，
   写 `toBiz` 转换 + 错误映射。
5. `ent/data.go` 的 `ProviderSet` 加上 `New<Resource>Repo`；`biz.ProviderSet` 加 usecase。
6. `make wire`。
7. 本地 `auto_migrate: true` 跑通；生产走第 6 步生成迁移 SQL 并评审。

## 排错速查

| 现象 | 原因 | 处理 |
|---|---|---|
| `schema directory not found` | 没在 ent 目录里跑 codegen | 用 `make ent`，或先 `cd app/user_center/internal/data/ent` |
| 生成的代码 import 了旧模块路径 | `generate.go` 的 `Package` 没改 | 改成新服务的 import path 后重跑 |
| id 列变成自增，插入报主键冲突/为 0 | 少了 `entsql.Annotation{Incremental: &false}` | 给主键字段加注解，`make ent`，并确认 repo 里 `.SetID(...)` |
| `unsupported ent driver: "sqlite"` | 模板已移除 sqlite | 用 `mysql` 或 `postgres`，本地跑 `make middleware-up` |
| 时间差 8 小时 | DSN 缺 `parseTime=true` 或 `loc=Local` | 补上 DSN 参数 |
| 唯一键冲突变成 500 | repo 没映射 `IsConstraintError` | 映射成 `biz.Err<Resource>AlreadyExists`（409） |
| 本地库和 schema 对不齐 | `Schema.Create` 不删列/不改类型 | 重建：`docker compose -f deploy/middleware/docker-compose.middleware.yaml down -v` |
| 翻页出现重复数据 | `Order` 没有确定的全序 | 末尾追加 `user.ByID()` 之类的稳定排序键 |
